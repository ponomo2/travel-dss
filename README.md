# Travel DSS

Python-реализация полного демонстрационного MVP СППР путешествий (этапы 1–8). Этап данных закрыт для MVP полным демонстрационным JSON API: 173 объекта, 72 предложения, календарь, расходы и матрицы. Маршрутизатор CP-SAT, сценарные риски, рекомендатель и Streamlit-интерфейс реализованы. Пользовательская приемка выполняется по руководству.  [Аудит и доказательства](reports/PASSPORT_AUDIT.md); [инструкция запуска дополнительных инструментов](docs/PASSPORT_TOOLS.md). Superset устанавливается отдельно и не заменяется Streamlit.

Подробный текущий статус и ограничения: [reports/STAGES_1_4.md](reports/STAGES_1_4.md). Исходный проект: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md). Протокол приемки: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md).

## Установка и передача

Начните с [HANDOFF.md](HANDOFF.md). Архив в `dist/` содержит исходники, данные, модели и тесты; `.venv` и локальное состояние не передаются.

```bash
python3.11 scripts/bootstrap.py
.venv/bin/python -m travel_dss.cli doctor
.venv/bin/python -m pytest -q
```

## Запуск системы

```bash
make app
```

Открыть [локальное приложение](http://127.0.0.1:8501). Руководство, интерпретация результатов и сценарии вашей проверки: [USER_GUIDE.md](docs/USER_GUIDE.md). Внутреннее устройство с прямыми ссылками на код: [INTERNALS.md](docs/INTERNALS.md). Техническая приемка и измерения: [STAGES_5_8.md](reports/STAGES_5_8.md).

```bash
.venv/bin/travel-dss recommend --allow-demo --output reports/my-trip.json --html reports/my-trip.html
make test
```

Полный поиск проверяет все выбранные направления и сочетания услуг, строит маршруты, показывает до трех различных вариантов, C50/C90, успешность сценариев и резерв при закрытии. Номинальные ограничения проверяются независимо. OPTIMAL/FEASIBLE и разрыв оптимальности не смешиваются. Цены и расписания демо; междугородние задержки и очереди отдельно не моделируются.

## Запуск

Исходная проверка выполнена на macOS arm64 / Python 3.9.6. Для передачи используется отдельная установка Python 3.11; ее результат — `dist/handoff_verification.json`. Фиксированные зависимости рассчитаны на Python 3.9–3.12. Более новые версии не поддерживаются этим набором колес.

```bash
python3.11 scripts/bootstrap.py
```

Для запуска без установки пакета:

```bash
export PYTHONPATH=src
.venv/bin/python -m travel_dss.cli validate-request examples/request.json
.venv/bin/python -m travel_dss.cli forecast sochi 2027-04-16 --request examples/request.json
.venv/bin/python scripts/criteria_demo.py
.venv/bin/python -m pytest -q
```

Весь анализ на сохраненных данных работает без сети после установки зависимостей. Superset устанавливается отдельно по docs/PASSPORT_TOOLS.md; пароль и локальные базы создаются на машине получателя.

## Данные и воспроизведение

```bash
export PYTHONPATH=src
.venv/bin/python scripts/fetch_weather.py
.venv/bin/python scripts/fetch_osm_map.py
.venv/bin/python scripts/prepare_catalog.py
.venv/bin/python scripts/fetch_osrm.py
.venv/bin/python scripts/train_forecast.py
.venv/bin/python scripts/criteria_demo.py
.venv/bin/python scripts/export_schemas.py
.venv/bin/python scripts/build_reports.py
```

Команды fetch_* загружают открытые данные и требуют сети; OSRM использует сохраненный сырой ответ при наличии. Повторная загрузка заменяет снимок; перед обновлением сохраните предыдущую версию, если она нужна для сравнения. JSON-модели и отчеты воспроизводятся без обучения по сети. `fetch_osm_map.py --city kaliningrad` обновляет только один город. Альтернативный `fetch_osm.py` использует Overpass; при реализации его сервер оказался недоступен, поэтому рабочий снимок получен через официальный OSM Map API.

Историческая погода — ERA5, 2015–2025, три показателя: максимальная суточная температура, осадки и максимальный ветер в km/h. Сохранены сырые ответы, CSV, единицы, URL, время получения и SHA256. Разбиение не использует 2025 год для выбора модели. Метрики и график: [карта модели](reports/forecast/MODEL_CARD.md).

OSM-снимок содержит объекты и локальную сеть улиц. Исходный каталог `data/processed/pois/` имеет статус кандидатов: цена отсутствует, часы работы из OSM требуют официальной проверки. `verified=false` и неизвестные поля не позволяют выдать подтвержденное решение. Эвристические темы и длительность явно отмечены как экспертные значения. В `*.review.json` находятся найденные официальные сайты для ручной проверки.

Экспериментальные матрицы получены Дейкстрой по пешеходным OSM-путям, а время — при экспертной скорости 4 km/h. Они не являются обещанной проверенной матрицей OSRM: не учитывают все барьеры, сигналы и ограничения; граница выгрузки может обрывать сеть. Сохранены статус `confirmed=false`, длины привязки и `null` для неподдержанных пар. `import_osrm` принимает внешнюю матрицу foot с обязательной версией снимка. Дополнительно сохранены реальные матрицы публичного FOSSGIS OSRM в `data/processed/osrm/`, отдельно от экспериментальных. URL, порядок точек, время запроса и хеш ответа фиксируются; точная версия удаленного графа при отсутствии data_version неизвестна. Входы объектов требуют проверки. [Условия FOSSGIS](https://routing.openstreetmap.de/about.html), [исправить карту](https://www.openstreetmap.org/fixthemap).

На текущем Python 3.9 TLS публичного OSRM-сервера не согласовывается. Сырые ответы загружены вспомогательным `python3 scripts/fetch_osrm_raw.py` на Python 3.15 с requests, затем валидированы и преобразованы `scripts/fetch_osrm.py` в основном окружении. По сохраненным сырым ответам последняя команда работает офлайн; обход проверки сертификатов не применяется.

## Добавление котировок и проверенных объектов

Для реальных предложений остается ручной импорт. Демонстрационный API уже заполнен отдельно; он не требует пользовательских цен. Пустой шаблон для реальных котировок: `data/templates/quotes.csv` или `quotes.json`. JSON Schema описывает поля. `total_rub` — полная стоимость пакета (транспорт туда-обратно либо все ночи проживания); `start/end` — начало и конец покрываемой услуги с часовыми поясами. `observed_at` — время получения предложения, а `valid_from/to` — даты покрываемой поездки. Это разные понятия; срок свежести дополнительно проверяется методом `Quote.usable` (24 часа по умолчанию).

```bash
export PYTHONPATH=src
.venv/bin/python -m travel_dss.cli import-catalog \
  --pois data/templates/pois.json --quotes data/templates/quotes.csv
```

Команда **атомарно заменяет** таблицы каталога SQLite переданным снимком. Пример выше импортирует пустые шаблоны; для рабочего каталога передайте заполненные файлы. Подготовленный OSM-каталог можно восстановить `scripts/prepare_catalog.py`.

При проверке объекта нужно указать официальную цену и расписание, обновить источник, дату и заметку проверки, а затем установить `verified=true`. Произвольная строка `opening_hours` не преобразуется автоматически в календарные окна. Для последующей маршрутизации предназначена `OpeningInterval`: конкретное окно с датой, часовым поясом и временем последнего входа. Сложные OSM-расписания нельзя угадывать.

## Модули

- `domain.py`: анкета, предпочтения, объекты, происхождение данных, котировки и окна работы.
- `data.py`, `osm.py`: получение и проверка данных, импорт JSON/CSV, SQLite, экспериментальная сеть.
- `preferences.py`: I/K/W/F, насыщение интересов, вклады, сравнение, Парето и чувствительность фиксированных вариантов.
- `forecast.py`: сезонная baseline, Ridge, временная валидация, интервалы, погодные блоки, JSON-артефакты.
- `validation.py`: предварительная проверка полноты каталога; это не проверка выполнимости еще не построенного маршрута.
- `cli.py`: проверка анкеты, прогноз и импорт.

Полезность не является вероятностью удовлетворенности. Ранжирование критериев не подтверждает соблюдение бюджета или времени: это обязанность независимого валидатора маршрута, реализованного в routing.py. Погодные интервалы эмпирические, их фактическое покрытие приведено в отчете.
