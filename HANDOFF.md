# Передача проекта другому разработчику (macOS)

## Что требуется от владельца проекта

Готовый комплект находится в `dist/`:

- `travel-dss-0.2.0.zip` — исходники, данные, обученные модели, тесты и документация;
- `travel-dss-0.2.0.zip.sha256` — контрольная сумма архива;
- `handoff_verification.json` — результат независимой установки и проверки распакованной копии, если такая проверка выполнена.

Передайте ZIP и SHA256-файл одним способом (например, файлом в мессенджере, облачной папкой или через репозиторий). Передавать вашу `.venv`, устанавливать что-либо на компьютер получателя или вручную заполнять цены не требуется. Файлы с логами проверок можно передать дополнительно. Инструкции для дополнительных инструментов: [docs/PASSPORT_TOOLS.md](docs/PASSPORT_TOOLS.md). Superset устанавливается в отдельную среду на Python 3.11, Protégé и Microsoft Excel — отдельно; для основного CLI/Streamlit они не нужны.

Архив уже содержит необходимые снимки. API-ключи и аккаунты внешних сервисов для проверки MVP не нужны. Кеш рекомендаций, обратная связь, локальные SQLite-базы, `.venv`, служебные каталоги и произвольные пользовательские отчеты не включаются. Реальные OSM/ERA5/OSRM-источники и синтетические данные четко обозначены.

Если после подготовки вы изменили код или данные, пересоберите архив и повторите контрольные команды:

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/build_internals_doc.py
.venv/bin/python scripts/build_release.py
```

Имя архива соответствует версии из `pyproject.toml`; при новой передаче с изменениями удобно увеличить эту версию. Не пересылайте старую SHA256-сумму с новым архивом. Исторический отчет `handoff_verification.json` относится только к указанной в нем сумме ZIP, поэтому после пересборки проверку надо повторить либо явно сообщить, что новый ZIP еще не проверялся.

## Что требуется от получателя

- macOS с 64-битным Python **3.11**, Terminal и браузер;
- доступ в интернет для первоначальной установки Python-зависимостей из PyPI;
- ориентировочно 2 ГБ свободного места для окружения, исходников и временных файлов.

Рабочий код также допускает Python 3.9–3.12; для передачи основной вариант — 3.11. Python 3.13/3.14/3.15 не подходит для зафиксированного набора колес научных пакетов. Версии библиотек фиксированы в `requirements.lock`. Полностью отдельная проверка выполняется на macOS arm64; Intel Mac отдельно не испытывался, pip выберет колеса своей архитектуры или сообщит об их отсутствии. Числа версий среды указаны в `handoff_verification.json`.

Если `python3.11` отсутствует и у разработчика уже есть Homebrew:

```bash
brew install python@3.11
python3.11 --version
```

Источник команды: [официальная формула Homebrew](https://formulae.brew.sh/formula/python@3.11). Альтернатива — подходящий установщик с [python.org](https://www.python.org/downloads/macos/). Не нужно заменять системный Python или устанавливать пакеты с `sudo pip`.

### 1. Проверить архив

В каталоге, где лежат ZIP и SHA256:

```bash
shasum -a 256 -c travel-dss-0.2.0.zip.sha256
unzip travel-dss-0.2.0.zip
cd travel-dss-0.2.0
python3.11 scripts/build_release.py --verify .
```

Ожидается `OK` для архива и сообщение о соответствии всех файлов манифесту. SHA256 выявляет повреждение или отличие файла от переданного; она сама по себе не удостоверяет личность отправителя.

### 2. Создать новое окружение

```bash
python3.11 scripts/bootstrap.py
```

Скрипт создает `.venv` в распакованном проекте, устанавливает фиксированные зависимости, затем проект в editable-режиме и выполняет `pip check`. Чужое окружение не переносится. Скачиваются готовые колеса; компилятор и повторное получение туристических данных не требуются.

Если `.venv` уже существует, проверяется версия ее Python. Окружение другой версии не удаляется автоматически: его можно переименовать, затем повторить установку. Если проект переносится в другой каталог после установки, `.venv` следует создать заново, поскольку сама виртуальная среда не переносима.

### 3. Проверить среду и файлы

```bash
.venv/bin/python -m travel_dss.cli doctor --verify-manifest
.venv/bin/python -m pytest -q
```

В `doctor` ожидаются `ok: true`, `demo_data_ready: true`, шесть городов, по 4018 погодных записей на каждый и по четыре прогнозных дня. В pytest не должно быть `failed` или `error`. Точное число тестов выводится в конце; возможны предупреждения устаревшего синтаксиса в сторонних Matplotlib/pyparsing.

Проверка манифеста предназначена для исходного распакованного снимка. Если разработчик изменит включенный файл, обнаруженное отличие нормально и должно быть объяснимым. После намеренных правок запускайте `doctor` без `--verify-manifest`, затем тесты и новую сборку релиза.

### 4. Проверить приложение

```bash
.venv/bin/python -m streamlit run app.py
```

Открыть [http://127.0.0.1:8501](http://127.0.0.1:8501). Сервер привязан к localhost, телеметрия отключена в `.streamlit/config.toml`. При занятом порте: добавить `--server.port 8502` и открыть этот порт. Остановка — `Ctrl+C` в терминале.

Пошаговый сценарий приемки: [docs/USER_GUIDE.md](docs/USER_GUIDE.md). Внутреннее устройство со ссылками на код: [docs/INTERNALS.md](docs/INTERNALS.md). Ссылки в этом документе относительные, поэтому работают после распаковки в другой каталог.

### 5. Проверить расчет из командной строки

Быстрая проверка каталога и прогноза:

```bash
.venv/bin/python -m travel_dss.cli catalog kazan --allow-demo
.venv/bin/python -m travel_dss.cli forecast sochi 2027-04-16 --request examples/request.json
```

Полный поиск с новым расчетом, без кеша:

```bash
.venv/bin/python -m travel_dss.cli recommend --allow-demo --no-cache \
  --output reports/check-result.json --html reports/check-result.html
```

Ожидаются допустимые варианты, метаданные и файлы JSON/HTML. Подробное число вариантов и последовательность мест могут отличаться: оптимизация ограничена реальным временем. Сравнивать нужно выполнимость, стоимость, объяснения и статусы, а не побайтовое совпадение маршрута. OPTIMAL и FEASIBLE имеют разный смысл; высокий риск отмечается отдельно. Для быстрого дополнительного прогона можно ограничить поиск `--cities kazan --seconds 15 --pair-seconds 1`.

Питание, все ночи и трансферы должны входить в смету. На независимой проверке по умолчанию 1000 сценариев, в планировании 100. Цены и расписания демонстрационные, они не превращаются в реальные предложения при запуске на другой машине.

## Что вернуть владельцу после проверки

Укажите macOS, архитектуру (`uname -m`), версию Python, вывод `doctor`, итог pytest и найденные отклонения. Приложите JSON/HTML результата с параметрами запроса. Для каждого замечания: действие → ожидание → фактическое поведение → соответствующий отчет. Оригинальный ZIP и его SHA256 лучше сохранить для сравнения.

## Интернет, зависимости и исходные данные

После установки Python-зависимостей каталог, прогноз, оптимизация, тесты и координатная схема работают без сети. Не запускайте `fetch_*` для обычной проверки: они обновляют исходные снимки и зависят от внешних серверов. Уже обученные модели и история включены в архив.

Установка без интернета тоже возможна, но требует отдельного wheelhouse, собранного для той же версии Python, macOS и архитектуры. Сам ZIP не включает сотни мегабайт зависимостей. Подготовка на совместимой машине:

```bash
python3.11 -m pip download --only-binary=:all: -r requirements.lock -d wheelhouse
python3.11 scripts/bootstrap.py --wheelhouse /path/to/wheelhouse
```

Это дополнительный вариант, не обязательный для обычной передачи. Колеса для Apple Silicon нельзя использовать как окружение Intel Mac. Внешние источники и их обозначения перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

## Границы пакета поставки

Это исходный проект с данными, устанавливаемый **editable** из распакованного каталога. Одиночный Python wheel без `data/` и `artifacts/models/` не является готовой поставкой приложения. Поиск корня проекта осуществляется относительно исходного модуля и не содержит вашего имени пользователя или жестко заданного `/Users/...`.

SQLite-снимки можно восстановить командой `.venv/bin/python -m travel_dss.cli sync-catalog --allow-demo`; приложение работает непосредственно с JSON, поэтому их отсутствие в ZIP штатно. Кеш создается при первом поиске. Тесты формируют свой результат самостоятельно и не зависят от личных отчетов предыдущего разработчика.
