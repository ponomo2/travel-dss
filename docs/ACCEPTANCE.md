# Постановка и приемка этапов 1–4

ЛПР — один совершеннолетний путешественник из Москвы. Решение — направление и маршрут на 2–5 дней в пределах одного города; расчетная валюта RUB. Состав направлений, критерии и границы сохранены в IMPLEMENTATION_PLAN.md. Три предлагаемых окна поездок находятся в data/trip_windows.json; по последующему поручению от 12.11.2026 цены и прочие атрибуты предоставляются полным демонстрационным JSON API (docs/DATA_API.md).

Анкета реализована как TripRequest и JSON Schema. Поля: временные границы с часовыми поясами, бюджет, интересы, четыре веса, погодные пороги, ходьба, длительность активностей, обед и запас, требуемая успешность, обязательные и исключенные объекты. Пример — examples/request.json. Swing weighting принимает баллы всех четырех критериев и нормирует их в единицу. Все ограничения применяются до интерпретации итоговой полезности.

Связь с семью требованиями: критерии и многокритериальность реализованы сейчас; погода и эмпирические блоки обеспечивают входы для учета неопределенности; прогноз обучен и проверен; маршрутизация и полный рекомендатель относятся к этапам 5–6; UI и несколько выполнимых вариантов относятся к этапам 6–7. Ранжирование фиксированных критериев не подменяет будущую оптимизацию маршрута.

Неопределенная доступность не превращается в высокую вероятность. OSM-кандидат не считается подтвержденным объектом до проверки официального расписания и цены. Отдельная экспериментальная матрица по OSM полезна для исследования покрытия, но не имеет статуса проверенной матрицы OSRM.

Этап 2 принят для demo-MVP: проверены 173 объекта, календарь, 72 предложения, питание, трансферы, шесть расширенных матриц, явный режим demo, единый контракт JSON/HTTP/SQLite. Подробная приемка: tests/test_catalog_api.py; машинный результат: reports/data_coverage.json. Официальная верификация для реальных бронирований не является частью принятого demo-набора.
