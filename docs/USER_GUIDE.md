# Руководство пользователя и приемочная проверка

Система помогает сравнить направления и маршруты одного взрослого из Москвы. Работа происходит локально, без бронирования и оплаты. В демонстрационном каталоге цены и часы работы смоделированы. Историческая погода и исходная география сохранены из реальных источников.

## Запуск

Из корня проекта после установки зависимостей по README:

```bash
.venv/bin/streamlit run app.py
```

Открыть http://localhost:8501 в браузере. Для командного режима:

```bash
.venv/bin/travel-dss recommend --allow-demo \
  --output reports/my-trip.json --html reports/my-trip.html
```

По умолчанию расчет охватывает шесть городов, все четыре сочетания транспорта и проживания в каждом городе, 100 плановых и 1000 независимых проверочных сценариев. Один поиск ограничен 60 секундами; для отдельных сочетаний по умолчанию 2 секунды (максимум 10). Фиксированный seed воспроизводит сценарии, но повторный поиск без кеша может закончиться другим допустимым решением из-за остановки по реальному времени. Повторение того же demo-запроса использует кеш, привязанный к запросу, коду, каталогу, моделям и параметрам расчета.

## Как выбрать поездку

1. Выберите одно из трех поддерживаемых окон 2027 года. Произвольные даты требуют соответствующего набора предложений и календарей; их отсутствие не заменяется выдуманным ответом.
2. Укажите бюджет **на всю поездку**. В него входят дорога туда-обратно, все ночи, питание, два трансфера и входные билеты.
3. Выберите города и предел ходьбы в день. Для первого знакомства можно оставить все шесть.
4. Задайте дневной лимит: он включает переходы, посещения, обед и ожидание открытия. Начало прогулки по принятой политике — не раньше 09:00, обед 12:00–15:00 около базы. Первый день начинается после прибытия/трансфера/заезда. В последний день выезд из номера до прогулки, багаж остается у путешественника; трансфер забирает у базы. Отдельного хранения багажа модель не обещает.
5. Распределите баллы интересов: культура, история, природа, гастрономия. Отдельно распределите баллы улучшений четырех критериев: интересы, экономичность, погода, удобство. Система нормирует каждую группу. Нулевая сумма недопустима.
6. Укажите комфортный диапазон суточной максимальной температуры, осадки и ветер. Это предпочтения, а не обещание погоды в каждый час.
7. При необходимости выберите обязательные и исключенные места. Один объект не может находиться в обеих группах; обязательные объекты разных городов делают однонаправленную поездку невозможной.
8. Нажмите «Подобрать путешествие». Дождитесь завершения сравнения; счетчик показывает проверенные комплекты услуг.

## Как читать результат

Система показывает до трех достаточно различных вариантов. Если допустимых/различимых вариантов меньше, это указано явно. Варианты одного города должны достаточно различаться набором посещений; простая перестановка тех же объектов не создает новую рекомендацию.

**Балл** — взвешенная полезность по вашим предпочтениям, не вероятность удовлетворенности. Объяснение раскладывает разницу баллов на четыре критерия.

**Смета** — стоимость базовых предложений и посещений. **Средняя сценарная стоимость**, **C50** и **C90** рассчитываются по сумме всех расходов внутри каждого сценария. C90 означает: в 90% проверочных сценариев модельная стоимость не превышает указанное число. Это не гарантия поставщика.

**Успех сценариев** — одновременное соблюдение бюджета, расписания и возвращения к отправлению. Если нижняя граница 95%-го интервала доли успеха ниже вашего порога, вариант не маркируется устойчивым по модели. Он может оставаться в сравнении с явным предупреждением.

**OPTIMAL** доказывает оптимальность целочисленной задачи для данного пакета услуг, каталога и плановой сценарной выборки. **FEASIBLE** подтверждает найденный допустимый маршрут, но оптимальность не доказана. Разрыв с границей оптимума показывается, если он доступен; отсутствие границы не трактуется как нулевой разрыв. Общий выбор — лучший среди фактически построенных кандидатов, с учетом ограничений времени поиска.

В расписании указано местное время города. Последний переход к базе указан отдельно для каждого дня. Координатная схема показывает порядок точек прямыми линиями; это **не** геометрия улиц. Длины и времена берутся из матрицы. Схема и все остальные функции доступны без сети.

Проверка закрытия объекта — отдельный стресс-сценарий. Если найден резерв, его можно скачать; он заново проверен. Если закрыт обязательный объект, система сообщает конфликт, не отменяя ваше требование. Вероятность самого закрытия не назначается.

Кнопки JSON/HTML сохраняют отчет на компьютер. «Выбрать/Отклонить» сохраняет решение и причину только в локальную базу проекта; предпочтения автоматически не меняются.

## Проверка системы пользователем

Пользователь выполняет эту проверку после знакомства с руководством и сообщает замечания. Исследование на 5–8 участниках и показатель понятности 80% пока не проводились; этот документ не выдает техническую проверку за пользовательское исследование.

| № | Действие | Что проверить |
|---|---|---|
| 1 | Оставить настройки по умолчанию | Появились объясненные варианты или конкретные причины отсутствия; нет непомеченных реальных цен |
| 2 | Открыть маршрут и смету | Все посещения в окнах, есть обед и возврат, сумма статей совпадает со сметой |
| 3 | Сопоставить таблицу с координатной схемой | Порядок объектов соответствует расписанию; прямые линии не названы реальным маршрутом улиц |
| 4 | Увеличить приоритет природы или культуры | Изменения маршрута/баллов объясняются интересами; лидер не обязан меняться при любом малом изменении |
| 5 | Снизить бюджет до 1000 ₽ | Нет ложного допустимого маршрута; исходный бюджет не увеличен автоматически |
| 6 | Снизить дневной лимит до 120 минут | Указана невозможность политики дня либо корректное отсутствие результатов; обед не исчезает |
| 7 | Сделать один объект обязательным | Он включен ровно один раз либо указан конфликт |
| 8 | Поместить тот же объект в исключенные | Ошибка ввода без старого результата под видом нового |
| 9 | Сравнить C90 и долю успеха | Различаются денежный риск и совместная успешность; есть предупреждение о модельных предположениях |
| 10 | Открыть стресс-проверку | Понятно, что закрылось, найден ли резерв и чем он отличается; отсутствие резерва не скрыто |
| 11 | Скачать JSON и HTML | Файлы открываются, содержат выбранные планы, даты, расходы и происхождение |
| 12 | Повторить тот же запрос | Используется кеш; изменение бюджета/весов приводит к новому ключу расчета |
| 13 | Отключить интернет | Работа со снимком и схема сохраняются |
| 14 | Сохранить выбор/отклонение | Подтверждение локального сохранения; нет отправки данных третьим лицам |

Форма замечания: параметры запроса → ожидаемое поведение → фактический результат → имя JSON/HTML-отчета → насколько понятна причина рекомендации (1–5). Рекомендуем сохранять отчет вместе с замечанием: в нем есть версии данных, моделей, кода и seed.

## Известные границы

Дополнения версии 0.2.0: в форме доступны AHP со строгой проверкой CR и выбор PuLP/CBC. При AHP нормированные баллы не определяют веса: используются шесть сравнений. Карточка показывает вывод правил и анализ стратегии резерва; указанный порог закрытия — условие выгодности при заданных потерях, а не измеренная вероятность. Ссылка BI ведет в отдельный локальный Superset; он показывает последний явно экспортированный результат. Установка BI, Excel и Protégé: [PASSPORT_TOOLS.md](PASSPORT_TOOLS.md). В приемке дополнительно проверьте смену весов при редактировании сравнений, отказ несогласованной матрицы, оба решателя и обновление BI после экспорта собственного JSON.

Поддерживается один город на поездку, один взрослый, один вариант жилья и конкретные покрытые даты. Багаж, очереди и задержки междугороднего транспорта отдельно не моделируются. Погода долгосрочная сезонная; ее интервалы для ряда городов недопокрывают номинальный уровень. Время и цены сценариев основаны на экспертных диапазонах демонстрационного набора. Результаты подходят для проверки логики СППР; реальная покупка потребует актуальных предложений и проверки расписаний.
