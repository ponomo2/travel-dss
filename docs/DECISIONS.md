# Уточнения реализации

1. **Сначала библиотека и CLI.** UI отложен до этапа 7 по плану. Доменная модель и расчет критериев доступны независимо от приложения.
2. **Демонстрационный API.** Новым поручением пользователь разрешил закрыть этап 2 JSON-данными, имитирующими ответ API. Создан отдельный полный снимок `data/api/demo_catalog.json`; он явно помечен `mode=demo`. Это заменяет прежнее решение ждать пользовательских цен. Реальные OSM/ERA5/OSRM-источники сохранены отдельно; синтетика не получает статус проверенных предложений.
3. **Источник OSM.** Overpass не ответил; использован официальный Map API с маленькими выгрузками центра каждого города. Это ограничивает географическое покрытие; отсутствие объекта в снимке не означает его отсутствия в городе.
4. **Координаты Калининграда.** При проверке каталога исправлена ошибочная исходная долгота центра на 20.5109, соответствующая центру города; обновлены и картографический, и погодный снимки. Для проверяемости URL запроса содержит координаты.
5. **Матрицы.** Сохранены отдельные экспериментальные матрицы по локальному OSM-графу. Они позволяют исследовать связность, но не заменяют проверку входов. Дополнительно используется кешируемый OSRM foot-снимок публичного FOSSGIS-сервера вместо локального развертывания. Его условия: https://routing.openstreetmap.de/about.html . Массовая нагрузка не предусматривается; для последующих этапов остается возможность локального OSRM.
6. **Сезонная шкала.** День года отображается на високосный 2000 год, чтобы не сдвигать март–декабрь в високосные годы. Гармонический период 366, линейный тренд в годах по 365.25 суток. Это явное уточнение формулы плана.
7. **Выбор прогноза.** Baseline остается итоговой моделью всех городов, поскольку Ridge не достигает установленного улучшения 5% на валидации. Сложность модели не является критерием качества.
8. **Недопокрытие интервалов.** На независимом 2025 году оно измерено и опубликовано; интервалы не расширяются по просмотренному тесту. Для улучшения нужна новая независимая проверка, а не подгонка отчета.
9. **Численная воспроизводимость.** В текущем macOS-окружении BLAS при умножении малой матрицы на вектор выдавал ложные floating-point warnings. Прогноз Ridge вычисляется `einsum` по тем же коэффициентам; изменения математической модели нет. Тест на чистой сезонности и сохранение/загрузка моделей проверяются автоматически.
10. **Доступность прогноза во времени.** Модель не может прогнозировать даты, уже использованные для калибровки. Метаданные отдельно фиксируют конец обучения точечной модели (2023), калибровку (2024) и тест (2025).

11. **Контракт поставщика.** JSON, HTTP и SQLite возвращают одну валидируемую модель CatalogSnapshot. HTTP-адаптер ожидает наш контракт; для Amadeus/Booking нужен отдельный перевод их формата и авторизованный доступ. При ошибке API нет молчаливого перехода на выдуманные предложения.
12. **Время демонстрации.** По умолчанию demo рассчитывается на момент generated_at снимка; этот as_of возвращается в каждой выборке. Явный as_of проверяет TTL, live использует реальное UTC-время. Демонстрационные цены не освежаются изменением timestamp при чтении.
